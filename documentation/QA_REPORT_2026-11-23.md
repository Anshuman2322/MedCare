# CureNeed — QA report (2026-11-23)

Full pre-deployment QA of `server/`, `client/` and `admin/`: code and config audit,
dependency audit, clean-install simulation of the Docker builds, automated tests,
real-browser QA (production builds, nginx security headers emulated), and a
production-mode boot test of the API.

**Verdict: ready to deploy once the owner-side items in §3 are done.** Two defects
would have made the first `docker compose build` fail; both are fixed (see §2).

## 2. Defects found and fixed

### Blockers (the first deploy would have failed or leaked)

| # | Finding | Fix |
|---|---|---|
| B1 | A clean `npm install` of `client` and `admin` crashes npm 10 (`Cannot read properties of null (reading 'edgesOut')`). Cause: any `vitest 4.1.x`. Docker installs without a lockfile, so the client and admin images could not be built. | `vitest` pinned to `~4.0.18`; fresh lockfiles generated and verified (`npm ci`, tests, build, audit) and un-ignored in `.gitignore`; Dockerfiles use `npm ci` when a lockfile is present. |
| B2 | No `.dockerignore`: `COPY . .` copied the host's Windows `node_modules` over the image's (wrong-platform esbuild/rollup binaries), baked `server/.env` (real secrets) into the image, and shipped ~135 MB of unused legacy images. | `.dockerignore` for `server`, `client`, `admin`. |

### High

| # | Finding | Fix |
|---|---|---|
| H1 | nginx dropped **all** security headers (CSP, X-Frame-Options, nosniff, Referrer-Policy) on the HTML and assets: a `location` that has its own `add_header` discards the server-level ones. | Cache rules rewritten with `expires`; verified in a browser with the exact headers from `nginx.conf` (no real nginx available, see §4). |
| H2 | With MongoDB unreachable in production (e.g. Atlas IP allow-list missing) the API served a legacy sample catalogue (1,400 images, fake prices) and saved admin edits into a JSON file. | `requireDatabase` middleware: catalogue, category and admin routes answer **503** in production. |
| H3 | Public, unauthenticated `POST /api/orders` accepted customer PII with no validation; nothing used it. | Endpoint, controller and model removed (docs updated). |
| H4 | Inquiry reference IDs were `count + 1`. Two simultaneous inquiries, or deleting any old record, produced a duplicate → unique-index error → the customer's inquiry was lost. | Next number = highest in use + 1, with retry on collision. Tests for both cases. |
| H5 | Docker images on `node:20` (end-of-life April 2026); API container ran as root, no health check. | `node:22-alpine`; server runs as `node`; `HEALTHCHECK` on `/api/health`. |

### Medium / low

- **Page weight:** `logo.png` was 2.1 MB (also the favicon) and the six hero "WebP" files were really 1.7 MB PNGs: logo → 92 KB, hero → ~60 KB each (−11.8 MB). Same names, same layout.
- **multer 1.x** (deprecated, known vulnerabilities) → **2.5.0**; `/api/upload` now accepts only JPEG/PNG/WebP/GIF (tested).
- JSON body limit 10 MB → **1 MB** on every route.
- A request from a foreign `Origin` returned **500**; now **403**. Expected 4xx errors are logged as warnings, not errors.
- The API container tried to serve a non-existent `client/dist` (error text exposed an internal path); it now serves the SPA only when the build exists.
- **Admin panel:** every page overflowed horizontally on a phone (top bar), the fixed *Menu* button covered the title; *My Profile* led to a page that does not exist (removed); unlabeled status selects and permission switches (now labelled / real switches); dashboard showed **"Rs. 0.00"** for every product because prices live on variants and are in US dollars (now `$12.50`, or `--`).
- **Storefront:** an unknown product URL said "Unable to load medicine details right now" (sounds temporary); it now shows the site's 404 page. `/reviews` added to the sitemap.
- Lint: 25 errors → 0. Five were false positives (`motion`, `<Illustration />` are used in JSX — the config now knows); the rest was dead code, including an unused category-description table with medical-sounding copy.
- `REVIEW_RATE_LIMIT_MAX` documented in `server/.env.example`.

## 3. Needs you (not changed by QA)

2. **`CORS_ORIGINS` is missing** from `server/.env`: set `https://www.cureneed.com,https://admin.cureneed.com` or the live site cannot call the API.

7. *Ocumoist Max Eye Drops* has no "strength".
8. Cloudinary upload preset (used from the browser): restrict formats/size/folder in Cloudinary. Enable database backups.
9. **Commit** the new `package-lock.json` files, the three `.dockerignore` files (both were git-ignored before; `.gitignore` now allows them) and the rest of the work. Nothing was committed or pushed by QA.
10. Optional: `client/public/medicines/`, `medicines_web2/`, `videos/` and the six source PNGs in `hero/` (~135 MB) are unused; Docker already skips them, you can delete them from the repo.

## 4. Not tested (be aware)

- **A real `docker compose up --build`:** Docker Desktop was not running. Each Dockerfile step was reproduced instead (clean copy, `npm ci`, tests, build, audit; server also booted in production mode). The first real deploy is the first container run — use the smoke test in `DEPLOYMENT.md`.
- **Real nginx:** the nginx security headers were checked by serving the production builds from a small Node server that sends the headers read from `nginx.conf` (CSP included). Running a downloaded nginx binary was not permitted in the QA environment.
- Sending real email (Resend), WhatsApp (Twilio), real Cloudinary uploads, Let's Encrypt issuance.
- Browsers other than Chromium, real phones, load testing.
- The repo's `e2e/` Playwright specs (they write to the real database).

## 5. How to re-run

```bash
cd server && npm test                         # 208 tests, in-memory MongoDB
cd client && npm test && npm run lint && npm run build
cd admin  && npm test && npm run build        # needs `npm ci` first (vitest was missing locally)
npm audit --omit=dev                          # in each app: expect 0
```

Clean-install check (what Docker does): copy an app to an empty folder without
`node_modules`, then `npm ci && npm test && npm run build`.
